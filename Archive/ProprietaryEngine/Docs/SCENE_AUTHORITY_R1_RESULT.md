# R1 — corrected scene authority

Implemented 2026-09-15 under the [correction plan](./ENGINE_CORRECTION_PLAN.md). Closes A01–A04 and the false-positive hierarchy assertion in A11. R2 live authoring hosting is next. This is CPU/domain proof, not a new renderer, visual acceptance, Windows result or completed human–AI engine.

## Delivered

- **Affine hierarchy:** derived column-major double matrices, indexed entities and cached deterministic parent-first evaluation. Matrix/normal values must remain finite and float-representable. Local editing remains TRS; world-space conversion and preserve-world reparenting reject unrepresentable shear instead of losing it. Parent-aware world edits avoid applying a selected parent's motion twice to its child.
- **Atomic publication:** transactions construct immutable candidate state, full validation, inverse history and changed-ID results before publication. `PreparedEdit::apply` checks base state/revision and swaps ownership without allocations, serialization or callbacks. Validation failures close the transaction. Stale prepared edits cannot overwrite newer work.
- **Structural history:** create, subtree delete/restore, duplicate, metadata, reparent and transforms share one transaction boundary. Group/ungroup can be composed from create/reparent/delete within that boundary. Undo and redo require explicit current revisions. High-water IDs survive undo/redo and persisted reload; IDs returned during staging are provisional until committed. Empty create/delete transactions do not poison history.
- **Saveable accepted state:** strict known fields, integer LOD 0–31, valid strings/tags, finite transforms, monotonic counters and a unified 1,024-entity/64-parent-link domain. The 1 MiB serialized envelope admission reserves worst-case counter-width growth so later undo/revision advancement cannot make retained source data unsaveable. Counter exhaustion is rejected before mutation; the last admitted revision remains readable.
- **Bounded history:** 64 entries and 16 MiB conservatively accounted retained payload, evicting oldest entries while retaining the latest required inverse. Shared states are counted again per entry, so accounting overestimates that sharing benefit. This is an authoring history budget, not total allocator/process-memory telemetry; external snapshots and allocator overhead need separate accounting in R2/R5.
- **Reliable adapter receipt preparation:** JSON success data is built before adopting the edit, and moved into the queued receipt afterward. Queue admission rolls back receipt/order storage on failure; a failed enqueue cannot leave an orphan request. Adapter copying/moving is prohibited because handlers capture the owner.

`worldMatrix` is the canonical derived query. The old `worldTransform` compatibility query is retained only for representable TRS and rejects shear. Inspection outputs `world_matrix`, not a misleading decomposed `world_transform`. Persisted authoring schema remains version 1; its previously documented optional component/tag fields still default when absent, while unknown fields now reject. Existing files exceeding the supported domain remain untouched and need an explicit import/partition decision; no content migration ran.

## Failure-path correction found during implementation

Exhaustive allocation injection found that the pinned nlohmann JSON container destructor uses an allocating flattening stack, and its scalar JSON/string comparison can allocate inside a nonthrowing comparison. Those could terminate preparation even before adoption. The engine now uses explicit string-reference comparison and allocation-free recursive cleanup for bounded temporary scene/receipt trees. This does not modify the pinned library or claim to harden every unrelated JSON caller. Command payload depth is checked before admission so request cleanup has a bounded stack depth. The existing live adapter remains synchronous until R2.

## Proof and limitations

[Evidence](../Evidence/R1-scene-authority/result.json) binds source hashes and the [native test transcript](../Evidence/R1-scene-authority/native-tests.txt). Freshly built and ran the three directly affected CTest cases: existing core documents/operations, existing scene tests and the new correction suite. All three pass. The correction test is registered, bringing the inventory to 16; unrelated tests were not rerun merely to increase the count.

The new tests independently verify affine/mirrored hierarchy expectations, shear rejection, inverse-transpose normals, world-space multi-selection, subtree history, duplicate IDs, mixed metadata/transforms, strict schema, stale prepared edits, revision exhaustion, zero-allocation publication and capacity-safe round trips. A 1,024-entity scene with 92 large metadata records saved at 1,045,820 bytes and reloaded unchanged. The next oversized candidate was rejected while preserving that file; retained history remained undoable and redoable.

Fault injection covered all allocation positions through successful completion for commit (60), undo (53), redo (53), adapter mutation/receipt preparation (66) and queue admission (32). Each injected failure preserved document values, revision and history. Original audit probe/evidence remains historical; the corrected regression suite establishes new expectations instead of overwriting those observations.

No generators, world profiles, authored constraints, persisted runtime deltas, renderer/physics ownership or UI widgets changed. Unity modifications were preserved. No application or gameplay smoke test was launched. A debugger attempt on the headless correction binary was stopped when it did not progress; no debug process is left running. Native Windows and graphical/gizmo acceptance remain open in their owning batches.
