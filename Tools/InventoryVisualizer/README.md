# Inventory interface study

Local browser prototype for fast iteration on Arc & Dust's Unity menu and inventory presentation. Run from this checkout:

```powershell
& .\Tools\InventoryVisualizer\Start.ps1
```

Open **http://127.0.0.1:8087**. Stop with Ctrl+C in the server terminal. Optional launcher arguments: `-Port 8088` or `-Python 'absolute/path/to/python.exe'`. The launcher prefers the installed Codex Python runtime; another Python requires `openpyxl`. No npm installation, build, Unity launch, or package change is needed. The server binds only to loopback. Source edits appear after browser refresh.

## Current proposal

- Food organization, October 15: **Cooking ingredients** contains 23 culinary source stocks and intermediate ingredients, including the selected edible-fauna fractions previously in Biological resources. **Consumables** retains 31 finished servings and consumables: meals, bars, drinks and the existing livestock-feed block. Cooking tools keep their equipment classification. Item types, recipes, nutrition/edibility caveats, tiers, stable IDs and review choices are unchanged. The per-item move record is `Docs/Design/Items/FOOD_CATEGORY_SPLIT_2026-10-15.json`.

- Yellow item-review circle: toggle to flag an item for review. A marked item keeps its yellow check visible and hides the green Keep button. Marking a kept item clears Keep; clearing review reveals an unchecked Keep button. Trash remains available during review. Review flags persist by item ID in `ITEM_REVIEW_STATE.json`, separately from artwork status, without changing the master workbook.

- Compact entry menu, category rail, item grid/list, and persistent inspection panel. Hover an item (or focus it with Tab) to reveal its trash button and green keep circle. Touch layouts show the controls directly. Click the empty circle to keep/protect the item; its check stays visible and the trash button disappears. Click the check to unkeep it.
- Clicking trash permanently removes that item from the master `Items` roster and the browser inventory. Related item review/variant/relationship rows and recipes involving the removed item are cleared as dependent records; other master items are retained. Rows are cleared in place rather than shifted, preserving table bounds, row addresses, styles and other ZIP parts. Multi-item source lists retain their other entries, marking removed references. Existing linked summaries recalculate when Excel next opens the workbook; cached summary totals may remain stale until then. This modifies the design database only, not Unity item assets or game saves.
- Keep protection lives in `Docs/Design/Items/ITEM_REVIEW_STATE.json`, created on the first keep/unkeep action, keyed by stable item ID. It is shared by all browser sessions served by this checkout and enforced on the server. It is separate from artwork approval. Do not remove this file when transferring review choices.
- Writes use same-origin requests, a per-server token, revision checks, an in-process mutation lock and atomic file replacement. A stale page or protected ID cannot delete a record. If Excel locks the workbook, close it and retry. Pre-delete source snapshots and deletion receipts are retained locally under ignored `Logs/InventoryVisualizer/Backups/` for file recovery; the UI has no trash bin or undo. Recovery snapshots are not published. The master is not rewritten by an openpyxl export: the adapter changes targeted OOXML row content and leaves unrelated archive members untouched.
- Reads the `Items` sheet of [the master workbook](../../Docs/Design/Items/MASTER_ITEM_DATABASE.xlsx) and checks its file hash every three seconds while the tab is visible. Saved spreadsheet changes refresh the item data automatically. Unsaved Excel edits cannot be read. Returning to the tab triggers a check. No exported roster to maintain. Cached formula values must already have been calculated in the workbook.
- Live updates preserve the current screen, owner, search, sort, valid filters, selected item (when it still matches), scroll positions, open inspection sections and browser artwork records. Removed categories/filter values fall back to all; a removed selection falls back to the first matching item. Updates wait while the inspector has focus, filter dropdowns are focused, or Appearance is open. The footer reports live, pending or retry status. A locked, missing or partially saved workbook leaves the last successful data visible and retries automatically. Each catalog response reads and hashes one in-memory workbook snapshot.
- **Reload spreadsheet** above the grid reads the latest saved workbook immediately, using the same state-preserving refresh. This is available alongside automatic updates; it does not reload the whole browser page or read unsaved Excel edits.
- Search spans source fields, including aliases, uses and source references. Search results may include related definitions as well as an exact name. Filters combine category, material tier, source design status and artwork state. Tier is not rarity. Missing mass, stack and rarity values remain undefined.
- Booter view sketches the six equipment spaces and four-pocket experiment from [the inventory brainstorm](../../Docs/Design/Gameplay/CAMP_LOOP_INVENTORY_REDESIGN_BRAINSTORM_2026-10-14.md). Its filtered library suggests broad equipment/supply categories, not approved slot compatibility. Legger view is a cargo browsing study, not actual carried contents. No equip, transfer, mass, capacity or physical-access simulation is implemented.
- Appearance controls compare worked iron, red oxide and mineral chalk; adjust tile size, text size and subtle generated surface grain. Preferences persist in this browser.
- Desktop windows at least 1600px wide display exactly ten items per grid row, with tighter card padding and wrapping names. Smaller windows retain the responsive tile-size layout; list mode is unchanged. The item-size slider applies to those smaller-window grids.
- Equipment classification, October 15: the 127 remaining entries formerly under Equipment are now **Armor (43), Tools (52), Accessories (15), Attachments (17)**. [Per-item decisions](../../Docs/Design/Items/EQUIPMENT_CLASSIFICATION.json) record every ID and category boundary. Armor covers protective wear, shields and complete guards; Tools covers active-use equipment, workshop fixtures and transport machinery; Accessories covers ordinary clothing, eyewear, personal reserves and carried utility gear; Attachments covers fitted mounts, inserts, liners and add-ons. - Artwork studio is secondary. Category silhouettes are explicitly labelled placeholders; no item artwork has been generated. Optional PNG/JPEG/WebP attachment, notes, art status, queue, draft prompt copy, and export/import support later visual iteration. Inventory hides those editing controls.

The quiet metal/mineral treatment is a proposal informed by [Sable's refined B–C study](../../Docs/Agents/Sable/work/2026-10-15-material-dioramas/refined_BC/README.md). The menu reads the existing workyard E review JPEG directly through a dedicated endpoint; it does not modify or duplicate the texture agent's files. The backdrop is an offline Blender render, not a Unity capture or new texture.

Artwork records are keyed by exact master item ID in IndexedDB; appearance preferences use localStorage. Browser profile, origin and port determine this storage, and clearing browser data removes it. Export workspace downloads a portable JSON backup including images and notes. Import merges recognized item IDs, replacing matching art records; unrelated records remain. Unknown IDs are skipped. Appearance is included in exports as a reference, but import currently restores only artwork records. Uploaded files are never written to the repository or master workbook. Attachment limit is 10 MB per image; workspace import limit is 100 MB. Avoid very large source images for icon studies.

## Scope and handoff

Crafting-station classification, October 15: **Crafting stations** contains Forge hearth, Controlled-heating firing kiln and Managed cooking firebox. The registered category appears in the left rail and category-move choices, with a furnace silhouette explicitly marked as a placeholder. The [reviewed item decisions](../../Docs/Design/Items/CRAFTING_STATION_CLASSIFICATION.json) cover the existing Tools roster, kiln candidate/lining and workshop upgrade. Reusable tools, crucibles, molds, mortar/pestle, cooking vessels, racks/stands, swage block and winding mandrel remain Tools; the kiln lining remains a component and abrasive disc remains a Workshop upgrade. Existing world-only workbench/refinery/sorter references do not acquire invented inventory records. `split_crafting_stations.py` stages a registry extension with Artifact Tool and uses preserving, hash-guarded category transactions to update linked caches, counts and the category dropdown before one production replacement. IDs, artwork/review state, formulas, styles, recipes and runtime behavior are retained. Local originals and verification receipts remain under ignored `Logs/CraftingStationsCategorySplit/`.

Category editing: in **Inventory → Item library**, drag a card onto a left-hand category or use **Move to category** in its inspector. A highlighted target names the destination; Escape or dropping outside a category cancels. All items is a browsing view, not a destination. Same-category drops do nothing. Registered categories remain available at zero, and an emptied selected category stays selected. Kept/review-marked items can be reclassified. Booter, Legger and Artwork studio remain browsing/artwork views; changing catalog classification does not transfer possessions or change Unity fitments.

The authoritative category registry is the `Categories` sheet's primary-category records (`CategoriesTable`, column E = `Primary category`), excluding overlapping families and planning groups. `/api/catalog` returns that list. On a successful category change, `category_edits.py` updates the master `Items.Category`, its search cache, exact-ID category records in Canister concepts, Item uses, Material routes and both Crafting browser sides, plus all primary-category count caches. It retains formula definitions. `Variants.Unity category`, tiers, slots, recipe semantics, classification history, item IDs/row positions, artwork and keep/review choices remain intact. The transaction maintains a contiguous `Categories!G6:G…` choice list with the `InventoryCategoryChoices` defined name and repairs the master category dropdown to reference it. This avoids shifting the fixed-address Taxonomy groups. Nonempty unrelated content in column G causes a safe rejection.

The server validates source revision and source/destination categories, creates a local source backup, builds a narrow OOXML candidate and verifies every original cell/formula/style plus the changed caches before atomic replacement. Source-hash checks and the existing in-process mutation lock coordinate server actions; independent Excel/script writers must coordinate too, because the process lock does not cover them. A locked workbook or detected conflict does not advance the UI. No production workbook is edited merely by loading the app; dropdown repair happens within the first successful move. This writes the local workbook only, not the separately retained Google Sheet.

Each category action has a UUID and immutable prepared/committed receipt files under ignored `Logs/InventoryVisualizer/Backups/`. The UI retains an interrupted operation ID in session storage and checks its status instead of blindly retrying; successful duplicate requests return the original receipt. If the process stopped between workbook replacement and receipt completion, the saved result hash can reconcile the operation. A changed file with an unresolvable outcome requires inspection before another move. **Undo** issues a new checked move for that item only, using the latest workbook revision and requiring the original destination still to be its current category. It never restores an old whole-workbook snapshot. The move notification and Undo button dismiss after eight seconds. Reloading the same tab preserves only the remaining time; expired notifications do not return. Saving and unresolved-operation messages remain visible until resolved. Local recovery snapshots/receipts remain.

Category verification: `python -m unittest test_category_moves test_item_review test_sync` from this tool directory covers registry/empty destinations, exact linked values and caches, untouched formulas/styles/archive members, protected-item movement, invalid/stale requests, no-op moves, idempotency, interrupted commits, file locks, external-writer conflicts, HTTP origin/token validation and Undo preserving an intervening item edit. The current production workbook's format is tested in memory. Browser checks use a disposable fixture and cover kept-item moves, Undo, native drag-and-drop, and retaining an emptied category. No real master item is moved for verification.

This is browser presentation and item-review tooling under `Tools`, outside Unity's import boundary. It follows the accepted [menu direction](../../Docs/Design/Gameplay/MENU_SYSTEM_DIRECTION.md) as context; its appearance and screen composition remain proposals. Controller integration, Unity UI implementation, actual gameplay inventory transactions and creative acceptance are separate work. Browser keyboard support covers Tab focus, arrow movement within the grid, `/` search and Escape back to menu. This does not establish Unity or gamepad parity.

Deterministic world identity, terrain/chunk streaming, generated-world objects and persisted gameplay deltas are not applicable: the tool creates no world objects, reads no live save, and issues no Unity commands. Existing master item IDs identify browser art and keep records. Greater Wasteland's authored constraints and always-loaded terrain remain untouched.
