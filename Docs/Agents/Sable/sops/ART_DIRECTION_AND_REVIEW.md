# Art Direction and Review SOP

1. **Orient.** Inspect branch, status, applicable instructions, the requested scope, and current sources. Identify production versus study assets and preserve concurrent work.
2. **Frame the brief.** Use the [art brief](../templates/ART_BRIEF.md). State the intended player experience, approved constraints, unresolved choices, deliverables, owners, and evidence needed. Workspace setup alone is documentation work; world identity and persistence are not applicable because no world objects are created or changed.
3. **Gather evidence.** Inspect relevant assets or supplied captures. For references record origin, date, intended lesson, and use restrictions when known. Separate reference inspiration from accepted game truth. Request missing creative information only when it materially affects the task; proceed with independent work meanwhile.
4. **Develop direction.** Describe silhouette, proportion, value hierarchy, palette, material behavior, and composition as needed. Explain how the proposal reads at the gameplay camera. Keep proposals bounded and compare them under equivalent conditions.
5. **Review visually.** Use the [visual review](../templates/VISUAL_REVIEW.md). Inspect the actual images and identify issues by location and effect. Check normal gameplay distance, relevant brighter-sunset/deeper-twilight conditions, ground contact, scale, and interaction readability when those views exist. Name missing views rather than inferring success.
6. **Hand off.** Give Blender a source/model brief; give Babineaux Unity-facing asset, material, lighting, or capture requirements; involve Lorekeeper for setting conflicts. Record exact paths, preservation constraints, unresolved choices, and the evidence expected. Gottspan controls integration order. These handoffs are records, not permission to start additional agents or message another chat.
7. **Verify and close.** Check documentation links and diffs for documentation tasks. Asset changes require format, metadata/reference, and relevant Unity checks through their owning lane. Record visual recommendation separately from user approval and technical proof. Update durable decisions only when justified; commit the verified task-owned batch and report remaining limits.

For comparisons, keep camera, framing, exposure, lighting, resolution, and asset revision consistent except for the variable under review. Label any intentional differences. A concept or offline render cannot establish final production appearance or performance.
