## Preserved behavior and scope

All fixed native TerrainData, TerrainColliders and terrain GameObjects remain resident. Do not generate/stream terrain, modify elevations, disable physical traversal, teleport BigARM, reroll accepted objects, change graphics quality, or install the generated-world reference services. Existing dirty assets and concurrent terrain expansion remain outside this task. Packages, renderer migration, external publication and hands-on smoke testing are not authorized by this implementation.

Population will be procedural and chunk-organized. World identity includes explicit terrain/recipe/catalog versions; 256 m identity cells are the initial proposal, distinct from adjustable 64/128 m presentation units and 1024 m sector indexing. Assign candidate identity before placement rejection. Preserve sparse mutations and actor-relevant collision independently of visual residency. Authored constraints protect routes, spawn, camps and landmarks. Terrain expansion and placement version changes need retention/migration behavior; graphics changes cannot reroll the world.

## Dependency-ordered batches and gates

1. **Baseline and contracts.** Refresh scene/asset inventory and active ownership. Use bounded full-content captures, one rendering process at a time, memory headroom and a timeout; stop for sustained resource growth or lost responsiveness. A provisional 60 FPS / 1080p target and 1–2 ms population work budget are not measured guarantees.
2. **Resident terrain queries.** Remove rendering enablement from query eligibility, retaining active-object, native data, collider enablement, matching data and hole checks. Gate: focused negative-coordinate, seam, disabled-renderer and invalid-collision tests.
3. **Terrain rendering window.** Index native terrain once; select camera/shadow coverage through sectors; immediate visible arrivals, retained boundary margin and bounded departures. Runtime-only installation targets the production scene. Original flags restore on shutdown. Gate: compile/import and focused lifecycle/camera-union/shadow tests, then matched bounded Player timing and author visual acceptance before declaring performance acceptance.
4. **Targeted hitches.** Separately enforce failed-route retry deadlines / one route build per update; then immutable snapshot capture plus a single ordered background save writer. Keep collision checks, transaction boundaries, durable writes/backups/recovery, completion revisions and shutdown semantics. Each needs its own focused tests. Do not infer these hitches' magnitude from stationary render captures.
5. **Population identity/lifecycle.** Implement one canonical deterministic placement/state contract, neighbour ownership, protected masks, sparse mutations and save compatibility before dense presentation. Gate: order-independent output, negative/corner boundaries, unchanged IDs under presentation changes and recreation with deltas.
6. **Bounded population sector.** Use accepted art and masks, shared materials/meshes, LOD and bounded work units. Separate records, visual buffers and actor-relevant collision; prepare obstacles ahead of actors and route queries. Measure allocations, uploads, collider creation, startup and boundary transitions. Expand progressively only after tests, performance and author acceptance.
7. **Conditional experiments.** Larger terrain tiles, GPU indirect clutter, proxies/clipmaps and renderer-path changes remain separate measured decisions if the simpler approach misses its goals. They are not automatic prerequisites or permission for package/settings changes.

## Bounded placement and presentation checkpoint October 12

Protected disks/corridors include the maximum scaled footprint. Center plus eight perimeter probes reject unsupported ground, excessive slope and relief. Those samples do not prove exhaustive coverage of arbitrary holes inside a footprint. Native collision queries remain main-thread work; no worker may call this adapter.

Completed compatible plans commit accepted addresses to the existing population state before presentation. Cancellation prevents adoption. The planner does not select a production seed or write terrain. Rule changes affecting position/acceptance require recipe or constraint compatibility changes; accepted-address equality alone does not validate changed transforms.

`FixedTerrainPopulationPresentation` realizes accepted static prefabs using shared meshes/materials and existing LODGroups, pooling bounded instances. Preparation remains inactive; successor publication retires matching outgoing collision in the same work unit. Collision and visual relevance are independent, including during partial publication. Admission reserves pending acquisitions, caps pending cells and rejects requests without replacement headroom before preparation; callers must retry after releasing lower-priority cells or changing demand. Rejection preserves active coverage. Release keeps accepted receipts and saved removals. Mutation checks during preparation/publication prevent regrowth; later active gameplay mutations still need explicit presentation reconciliation through the future gameplay integration. Save restoration must cancel/release pending presentations before rebuilding demand.
