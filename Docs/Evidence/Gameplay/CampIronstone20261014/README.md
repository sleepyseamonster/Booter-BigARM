# Camp foundation and Ironstone sorting — October 14, 2026

The bounded first slice of the [audited implementation plan](../../../Design/Gameplay/CAMP_SYSTEM_AND_IRONSTONE_PROCESSOR_IMPLEMENTATION_PLAN_2026-10-14.md) is implemented in CampLoopTesting. This is a session-only lab, with provisional material names and yields.

## Player loop

Interact with a camp chest or workstation and choose **Camp Overview · Items**, **Camp Stations** or **Companions**. Items remain in their physical Booter, Legger, chest or sorter-output owner; inspection provides no remote transfer access. Station selection inspects unavailable/distant stations and opens executable details only within physical reach. The companion view shows the Legger's real proximity, follower/mount state and cargo access. Call closes the modal and requests his existing physical movement to Booter.

The manual Ironstone sorter has an eight-slot resource-only output tray. Choose accessible cargo or the chest, prepare and confirm one batch: **4 raw Ironstone → 2 coarse aggregate + 1 iron-rich concentrate + 1 mineral sand + 2 mineral dust**. Material mass is 5.0 before and after. All outputs must fit together; rejected/stale/corrupt/unavailable operations consume nothing. Mineral dust cannot substitute for Arc Dust. Retrieve a whole selected stack into legal nearby cargo/chest storage; a partly fitting stack is rejected in full. The tray accepts no player deposits. The old transfer screens retain their maximum-fit behavior.

No extra ore is granted. The battery recipe's four chest ore and the Arc refinery's ten-dust charging cost remain intact. Processing can consume the existing chest ore by an explicit player choice; gather additional ore when both activities are desired. Economy reset clears the tray/new product IDs, replaces chest recipe ore with four, and preserves cargo raw ore, unrelated items, salvage, actors and vitals. Full inventory trial reset retains its broader baseline scope and includes an empty tray; the old filled-Arc-socket guard remains.

## Architecture and retention

A Scene-local registry reuses waypoint identity `greater-wasteland.authored.v1` / `camp.starting`, existing station/cache IDs and `legger.primary`. Actor inventories are projected owners rather than camp copies. Station adapters retain existing services. Native terrain stays fixed/resident; no generation or streaming is introduced. The processor/tray have authored stable IDs. Existing canister-placement world identity and equipment payload formats are preserved.

Prepared processing captures source/tray references and revisions, processor revision, a recipe/catalog content fingerprint, registration generation/session token and economy epoch. Every participating inventory and scalar installs before observer publication. Install delegates perform prevalidated assignments; there is no claim of rollback after a throwing Install. The tray's version-1 presence/identity envelope retains slots, processor revision and an epoch consistency value, with EconomySession the only epoch authority. Required decimal counter strings reject missing/default counter data. Invalid retention is preserved and blocked, not converted to a fresh empty store. Runtime inventory revisions are reconstructed normally, with a new command token.

Reset participants compose inventory drafts and world mutations into one commit, with duplicate-owner checks and stale confirmation stamps. Baseline preflight precedes fresh grants. A legacy trial baseline extends once with a known fresh empty tray while retaining its original inventory/world snapshots. The same workstation modal/EventSystem owns all views; held controls, menu suspension, damage/death, focus/device loss, disable, missing components and source reconstruction invalidate unsafe commands. Subscription teardown retains managed state references so destroyed Unity presentation objects cannot leave a static input callback behind.

Process definitions bound individual quantities and stacks to 1,000,000, reject invalid resource metadata/IDs/overlap and conserve finite material mass within 0.0001. The current station interface previews one input and up to four outputs; larger recipe interfaces require a later extension and are blocked in the UI. The reusable process-definition validator supports up to eight inputs/outputs. Cutting, powered metal production, autonomous companion work and production disk persistence remain separate milestones.
