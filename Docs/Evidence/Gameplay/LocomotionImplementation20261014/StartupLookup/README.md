# Camp Loop early startup lookup repair

October 14, 2026. The author reported that F9 did nothing and Booter moved in a static pose. The author log records failed playground initialization and subsequent script reloads/UI exceptions. Read-only inspection in Edit Mode found valid private character, locomotion and forward-review assets, the authored player/collider, and the F9 binding. Those checks do not establish live playback.

The startup lookup rejected every scene with `Scene.isLoaded == false`, including its own calls from player preparation in `Awake` and input preparation in `OnEnable`. Unity [documents that this flag becomes true after objects have been enabled](https://docs.unity3d.com/6000.4/Documentation/ScriptReference/SceneManagement.Scene-isLoaded.html). This was a real initialization defect; the earlier fixtures manually invoked startup after opening a scene and missed that phase. Script reload damage during Play Mode remains a separate possible contributor to the observed static pose.

The session now registers its authored owner at the beginning of `Awake`, before preparing the character. Lookup checks that registered owner before requiring a fully loaded scene for hierarchy discovery. Existing scene identity checks and destruction cleanup remain in force. The deterministic regression supplies the pre-loaded phase explicitly: no owner means no hierarchy scan; after `Awake`, lookup resolves the session; after destruction it cannot reuse that owner. It never enters Play Mode or advances gameplay/physics.

The isolated candidate passed **304/304** playground Edit Mode checks with zero failures/skips, including **5/5** session checks. This is the complete current working candidate, including the separately developing turn-source tests. The two changed source files and original metadata pair byte-for-byte with the author checkout. The author Editor loaded the new lookup, with compilation finished and its dirty scene retained. See [verification.json](verification.json) and [editmode-tests.json](editmode-tests.json).

Only the session script and its existing test file were installed into the author project. No scene save/reload, Play Mode command, window activation, package operation or animation payload change was used. A fresh author-owned Play Mode session must still establish animation playback and F9 behavior; do not count this checkpoint as visual acceptance or a general solution for hot script reloads.

World identity uses the existing exact authored scene path and scene-local owner. Generated-object identity and terrain/chunk streaming do not apply: this repair creates no world content and the laboratory is authored and always loaded during a session. Scene unload removes the cached owner, and reload creates/registers the next owner. No persisted runtime delta, seed, save schema or checkpoint format changes; the existing laboratory session-only policy can now resolve its marker during early startup.
