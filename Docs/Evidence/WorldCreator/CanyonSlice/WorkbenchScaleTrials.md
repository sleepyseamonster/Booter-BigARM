# Workbench size trials on the generated canyon

Date: 2026-09-29. Both trials ran only in the isolated Unity mirror against the widened-apron candidate. The source Workbench assets, live dirty Unity checkout, and approved catalog were unchanged.

The first trial enlarged the existing terrain-screened `CliffStone_A-E` buttresses from a 3.5-5.5 scale range to 8-14 ([one-line patch](OversizedStoneTrial.patch)). The [same-pose image](OversizedStoneTrial.png) shows rounded dark stones glued onto the pale terrace face. Their size increases visibility but does not create a continuous geological mass or the reference's eroded layered cliff. This visual gate fails, so the change was restored before any production cutover. No collision or Player performance claim is made for the enlarged stones.

The second trial applied 2× scale to approved `HandbuiltSpire` composites whose reservation center sampled `CanyonShelf` or `CanyonWall`; floor formations kept their original scale. The full-footprint placement screen admitted no additional or enlarged wall composition. The [focused audit](OversizedCompositeAudit.xml) passed and again realized the same six approved formations, 118 member rocks, and five of 49 chunks as the widened-apron control. The visual overview was effectively unchanged. The trial was restored. This is evidence that enlarging existing stages cannot populate steep wall reservations under the current fit and route rules; weakening those screens would be the wrong fix.

A useful next prototype is a **new Rock Workbench wall or mesa formation** whose baked members form a connected ledge and weathered face at its intended scale. It needs a terrain-anchor and full-footprint contract designed for steep shoulders, then deterministic chunk ownership, low-detail collision, near/middle/far presentation, and a rendered Player cost comparison. The current `CliffWallSampleReference.prefab` contains 18 editable source rocks and is a possible authoring starting point, but it is not an approved runtime formation. Any candidate must be captured, baked, reviewed, and registered deliberately; merely multiplying an existing template is not equivalent.
