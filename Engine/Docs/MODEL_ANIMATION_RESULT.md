# Model Import and Animation First Pass

P11 implemented 2026-09-10. The engine now cooks a restricted glTF/GLB model into its own versioned data, samples and blends skeletal animation through ozz, and skins the model on the GPU in both the scene and sun-shadow passes. The workbench can preview clips or attach the imported proxy to the existing third-person capsule controller. The next package is P12's shared player application, interaction target and first audio cue.

## Data and ownership

`engine_model_cook` is the offline import boundary. `engine_animation` consumes engine-owned model records without exposing glTF types to runtime callers. `engine.model` version 1 stores hierarchy, inverse binds, clips and linear base-color/roughness/metallic factors. A checksummed `MSH1` mesh payload stores 68-byte vertices and 32-bit indices in little-endian form. Source UVs, tangent handedness and four normalized skin influences survive cooking. Output directories are immutable; the manifest is written only after its mesh payload closes successfully. A failed cook can leave an incomplete output directory, which the runtime cannot load; retry to a new directory.

Each animation instance owns its sampling cursors, local pose and joint palette. Immutable engine model data can be shared. This first pass compiles the validated records into ozz skeleton/clip objects when an animation instance is created; shared compiled-asset caching and background preparation remain later resource/scheduling work. It does not deserialize untrusted ozz archives. Ozz's compressed quaternion sampling is an approximation of source rotations, not a promise of exact glTF spherical interpolation at every time.

`RenderModel` owns GPU vertex/index buffers and releases them before renderer shutdown. Per-frame poses are borrowed only for draw submission. CPU skinning supplies a technical reference and does not replace the ordinary GPU path. Both the lit and shadow shaders use the same four-weight palette transform. Skin normals are normalized before interpolation. Imported PBR factors use linear values directly; the current model material uses scalar factors without image bindings. Transferred rock/ground textures retain their existing separate surface path.

The character motor owns world movement. Animation changes presentation only; it never writes physics positions or world identity. The calibration's first two clips are temporarily mapped to idle/walk, with a short blend driven by movement intent. Root-motion extraction, foot placement, retargeting and jump/run clips are not implemented. A source clip can contain skeletal translation, but it cannot move the authoritative motor. Preview offers clip selection, play/pause and blending to the next clip.

## Accepted source profile

The first import profile is deliberately explicit, based on the [glTF 2.0 specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html) and [ozz runtime documentation](https://guillaumeblanc.github.io/ozz-animation/documentation/):

- One scene, one mesh instance and one triangle primitive; static meshes or one skin. All nodes belong to that scene and have a single parent. Node scale must be baked into vertices. Translation and rotation are preserved; inverse-bind bases must be rigid and unreflected. Units follow glTF meters and Y-up.
- Up to 100,000 vertices, 300,000 indices, 127 source nodes, 64 palette joints and four influences per vertex. POSITION and NORMAL are required. TEXCOORD_0 and TANGENT are optional; absent tangents receive an orthogonal basis suitable for the current untextured material. Unsupported attributes are rejected.
- Up to 16 uniquely named clips, 600 seconds per clip and 8,192 total keys. LINEAR translation/rotation tracks only. Animated scale, morph targets, sparse accessors, compression/extensions, additional UV/color/influence sets and alternate interpolation modes are rejected.
- Opaque, single-sided scalar PBR materials. Embedded/external images, texture bindings, scene cameras/lights and emissive materials require another profile and are rejected.
- Source file and aggregate buffers are bounded to 32 MiB. External buffers must be relative, contained paths with matching lengths. Accessor layouts and byte ranges are checked before iteration. Cooked metadata is bounded to the existing 1 MiB document limit; mesh header, size and checksum are checked before use.

`Assets/Models/Calibration/character.glb` is a repository-owned technical proxy generated by `Tools/make_character_fixture.py`: seven cuboid body parts, seven skin joints, 168 vertices, 252 indices, idle and walk clips. It is test content, not Booter's final appearance or new setting canon.

Archive checksums and exact source identities are in `Research/runtime-lock.json`; primary MIT notices are retained in `Research/Licenses/` and the license manifest. simdjson offers MIT/Apache licensing; this integration retains its MIT option.

Ozz 0.17 required CMake 3.30; 0.16 works with the installed CMake 3.28 toolchain and requires 3.24. The engine minimum is now CMake 3.24. This avoids changing global development tools. Version updates remain explicit lock changes.

## Procedural-world contract

Model cooking introduces no world seed or placement identity. Asset identity and generated-object identity remain separate: a future chunk owner can reference the same model from multiple stable objects, allocate animation/render resources on load and release them on unload. GPU handles and sampling cursors never enter save data. Authored transforms and clip tracks constrain presentation. Persisted gameplay deltas belong to world/save owners; restore reconstructs presentation from authoritative state. Streaming, model-asset catalog identity and animation-state persistence are subsequent packages, not implicit behavior in this loader.

## Bounded evidence

[Native import/animation evidence](../Evidence/P11-runtime/result.json) records the successful cooker and focused CPU cases: GLB and contained-buffer glTF parsing, cooked round-trip, inverse-bind/rest pose, animated deformation, loop equality, blend endpoints/intermediate pose, static hierarchy translation, invalid joints, cyclic hierarchy, duplicate key time, clip bounds, corrupt mesh checksum, excessive accessor count, external traversal and unsupported extension/interpolation rejection.

[One five-capture Metal comparison](../Evidence/P11-animation/result.json) rendered rest, GPU walk, CPU walk, GPU normals and CPU normals. The walk changed 8,556 of 358,560 sampled pixels. GPU versus CPU differences above three code values were **zero** for both the lit/shadow result and normals. Captures completed with zero reported GPU errors and normal shutdown; the source, binary and shader identities are retained. This check did not exercise gameplay input or claim physical-character feel, general glTF fidelity, Windows behavior or final art quality.

The current build and source asset are usable through [the run instructions](./RUN_FOUNDATION.md). The earlier portable package is historical; the new model cooker/assets will enter P13's player package. No broad texture recook, unrelated regression suite, package loop or gameplay smoke test was run for this batch.
